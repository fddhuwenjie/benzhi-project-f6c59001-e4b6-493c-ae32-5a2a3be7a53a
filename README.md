# 古籍修复方案审议工作台

本项目面向古籍保护机构，用于将单件古籍从损伤建档、专业评估、方案编制、同行审议、小样核验推进到批准封存。系统保留每次状态变化的操作者、角色、请求标识、前后修订号和证据元数据，并可为已封存事项导出只读 JSON 审计包。

## 主要流程

1. 修复师建立损伤档案，并在提交前以修订号和幂等请求持续维护建档字段及图像证据。
2. 档案完整性校验通过后进入待评估，负责人逐个损伤部位登记等级、表现、影响范围、保护目标及不可干预边界。
3. 修复师编制材料、工序、环境要求、可逆性说明、风险控制和小样验收条件；被退回的方案和意见保留为不可变历史，新版本记录回应与字段差异。
4. 负责人可设置专家名册、回避人员和法定人数；未设置时沿用两位专家独立审议规则。
5. 修复师按方案版本保存不可覆盖的小样批次，记录逐项结果与偏差闭环，失败后可在新方案通过审议后引用原批次复测。
6. 负责人查看封存预检清单并确认提示项；批准时重新核对证据和事件链。已封存事项只读，可下载包含预检、证据索引、事件链摘要和内容摘要的 JSON 审计包。

## 构建

项目要求 Go 1.22 或更高版本。

    go build ./cmd/server

## 运行

默认监听高位回环地址 127.0.0.1:19081，数据保存在 ./data：

    go run ./cmd/server

可通过参数指定地址和数据目录：

    go run ./cmd/server -addr=127.0.0.1:19181 -data=./data

也可通过 PORT 提供端口号，此时绑定 127.0.0.1:<PORT>。显式 -addr 的优先级高于 PORT。启动后在浏览器访问对应地址即可使用工作台。

## 测试

运行全部单元与集成测试：

    go test ./...

运行有界全流程自检。该命令使用隔离临时目录和真实 HTTP 路由完成从建档到封存的流程，完成后主动退出：

    go run ./cmd/server -selftest -addr=127.0.0.1:19081

## 数据存储

仓储在数据目录下维护 cases 原子 JSON 快照、events 追加式 JSONL 事件日志和 requests 幂等结果。启动时会读取事件中的聚合快照恢复缺失或落后的事项快照。写请求必须携带 request_id 与 expected_revision，以处理重复提交和乐观并发冲突。

工作台使用原有 `/api/cases/{id}` 事项详情入口返回当前快照、历史版本、审议进度、小样批次、时间线及封存预检。草稿修订使用 `POST /api/cases/{id}/draft`，名册设置使用 `POST /api/cases/{id}/reviews/roster`，封存预检可通过 `GET /api/cases/{id}/precheck` 单独查询。
